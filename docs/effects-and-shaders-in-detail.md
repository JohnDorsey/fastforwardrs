# Effects and shaders, in detail

What an effect is, the effects there are, look-up tables, shaders (ISF files: filters, generators, passes of their own) and where the files that effects use are kept, with the rules behind each. It was part of [`using-the-editor-in-detail.md`](using-the-editor-in-detail.md), which says how to put an effect on something (*put an effect on a clip, a track or a group*) and where the effects of a group are done (*Groups*); this is the rest.

**Effects.** An **effect** is something done to the picture of a clip, or of a track (to everything seen on it), on its way to the finished picture. A video, a picture and a text object can have effects, and so can a track; a sound and a keyframe crate cannot. A clip, a track or a group has its effects in a **chain**, and may have several of one kind (two hue shifts, each with values of its own): they are done in the order they are in, first to last, and a new one is put last. The chain is shown in the properties panel as the boxes of the effects with **badges** among them, which say where the effects of something else are done to it (see *Groups*), and **the order is changed by dragging**. The effects of a clip are done in the order of its chain, with those of its **track** done at the place of the grey badge of the track (last in the chain until it is moved: so to begin with it is the effects of the clip, and then those of its track) and those of each **tag** it is in at the place of the badge of the tag; and after those, the effects of the **clip groups** it is inside, the nearest first, and then those of the **track groups** its track is in. What an effect does is set by its **values**, which are properties like any other: each is changed with a control in the box of the effect, has the stopwatch and the arrows of keyframes, and its keyframes are in racks in the drawers, named by the property (*Hue shift*, and when there are several effects of one kind, which of them: *Hue shift 2*). An effect that is put on has the values it begins with (a hue shift of nothing, which changes no colour); taking it off takes its keyframes with it. The **hue shift** turns the colours of the picture round the wheel of colours by its number of **degrees** (a third of the way round is 120): red goes to green and then to blue, as the *hue-rotate* of CSS does it, which keeps how bright a colour is as far as it can; a whole number of turns changes nothing, and how clear a pixel is is not changed. The number is not limited (the slider goes from half a turn back to half a turn on, and a number typed in goes further): between two keyframes the colours go round as many times as the numbers say. The picture of a clip is changed after it is put where it is (so a clip that is turned, or only partly on the picture, has all of its picture changed) and before it is turned, and what is changed in the preview is what is exported. The pictures on the **timeline** are the pictures of the file as they are, whatever the effects are.

*The effects there are.* Every effect has a value of nothing-changed that it begins with (a **default**: the effect does nothing until a value is changed), and its range ends do what they say.

| Effect | Values | What it does |
|---|---|---|
| **Hue shift** | *Turn*, in degrees (-180 to 180 on the slider, any number typed) | as described above |
| **Saturation** | *Amount*, 0 to 2 (1 changes nothing) | 0 makes every colour the grey it is as bright as; 2 doubles how colourful each colour is (a colour that this takes past what a screen shows is cut off) |
| **Brightness and contrast** | *Brightness*, -1 to 1 (0); *Contrast*, 0 to 2 (1) | contrast stretches the colours away from the middle grey, and brightness adds to them, on the numbers of the screen, as the controls of a monitor do |
| **Exposure** | *Amount*, in **stops**, -5 to 5 (0) | multiplies the light by 2 to the power of the stops: +1 is twice the light, -1 half, **in linear light**, as a camera's exposure is |
| **Opacity** | *Amount*, 0 to 1 (1) | makes the picture of the clip, or of the track, see-through by that much (the light of what is behind shows through) |
| **Blur** | *Radius*, 0 to 100 points (0) | a Gaussian blur **of light**. The radius is in **points of a picture 1080 high**, and is scaled with the size of the finished picture, so that the preview and the export of any size blur the same share of the picture |
| **Crop** | *Left*, *Top*, *Right*, *Bottom*, each 0 to 1 of the picture (0), and *Feather*, 0 to 0.5 (0) | what is cut off is clear; the feather softens the new edges |
| **Look-up table** | *Table*, *Intensity* 0 to 1 (1), *Input space*, *Output space*, *Interpolation* | see *Look-up tables* |

The colour effects (hue shift, saturation, brightness and contrast) are done on the numbers of the screen, and exposure, opacity, blur and crop in linear light (a look-up table in the space it says); the program converts between the two **once** where effects of the two kinds are next to each other, not at every effect. Effects that are next to each other and are done on the colours alone are **fused** into one matrix, so a chain of them costs one pass of the card. An effect that does nothing at the frame (a value at its default, or an effect that is switched off) is not asked for at all.

**At most 64 effects** can be on one clip, track or group; adding or copying the 65th is refused with a message, and a project file with more on one thing is refused when it is opened.

**Look-up tables.** The **look-up table** effect reads a `.cube` file (the table that colourists' programs write; 1-D and 3-D tables, and the variant of DaVinci Resolve is read but not written). A file is **read as a table before anything is changed**: one that is not a table is refused with the number of the line that is wrong and the project is left as it was. A 3-D table of **more than 65 points a side** is refused (it says so). A 3-D table is applied with **tetrahedral** interpolation by default (or **trilinear**), and a 1-D table is applied to each of the three colours by itself. The *Input space* and the *Output space* say what the numbers of the table mean: the **codes of a screen (sRGB)**, which is what a table made for pictures wants and is the default, **Rec.709 video (gamma 2.4)**, or **linear light (the working space)**; the program converts to the input space, looks the colour up, and converts back from the output space. *Intensity* mixes the result with the picture as it was, in light. Five tables of the program's own are in the folder `assets/luts` (*cool*, *faded*, *monochrome*, *punchy*, *warm*: made by a formula, `tools/make_sample_luts.py`, and given to the public domain, CC0); choose one with *Add effect from file...*.

**Shaders.** *Add effect from file...* also takes an **ISF** file (`.fs` or `.isf`: a comment at the top with the JSON of its inputs, and GLSL after it). The file is read and compiled before anything is changed, so a wrong one is refused with **the line and column of the file**; a good one puts an effect on the clip, the track or the group, with a control for each input (a number has a slider, a `long` is a list, a colour is a colour button, a point is two boxes to drag in; a picture is the layer's own). **The text of the file is kept in the project file**, so the project runs it on another computer, and no question is asked: a shader is data, and the worst it can do is waste time on the graphics card, which the program guards against. It works on the numbers of the screen (as hue shift does); `TIME` is the time since its clip began (for a track, a tag or a group, since the start of the timeline), never the computer's clock; and a point is in points of a picture 1080 high, so that it is in the same place at any size. **A shader that reads no picture is a generator**, made into a clip: **right-click an empty part of a track**, choose *New* and then *Generator from file...*. The clip lasts five seconds (or until the next clip), is selected, and has *Shown for*, *Position*, *Size* and *Rotation* (it is the whole picture until put somewhere, and can be moved, resized and turned on the preview: any shape) and the chain of effects every clip has. **The first effect of the chain is what it makes**, with controls and stopwatches for the shader's inputs; it cannot be taken off, switched off, copied or moved, and the effects after it are done to what it makes. A filter is not a generator: the wrong one is refused with the way to do what was meant.

**Passes.** A shader may have `PASSES`. Each is run on the whole picture and draws into the buffer its `TARGET` names (the last draws the picture the effect makes); a later pass reads a buffer by its name, `PASSINDEX` says which pass is running, `RENDERSIZE` is the size of what it draws, `inputImage` is the same in every pass, and a buffer that no earlier pass drew reads as clear. A buffer is as big as its `WIDTH` and `HEIGHT` say (an expression of `$WIDTH`, `$HEIGHT`, the shader's numbers and `floor ceil round abs min max pow sqrt sin cos exp log log2 sign`; the picture's size if not said; 1 to 8192), and holds **8 bits of each colour** (rounded to 8 bits, as the reference host does) or, with `FLOAT`, **half floats** (not 32 bits); at most 16 passes and 7 pictures.

**Buffers that last (`PERSISTENT`).** A buffer with `PERSISTENT` keeps what was drawn into it for the next frame (the program keeps two textures of it, however many frames there are). A pass that reads it before the pass that draws it reads **what it held when the frame before ended**; a pass after that reads what was drawn. **The first frame of a clip, and any frame that is not the one after the last made** (a jump, a frame skipped, a loop), **starts it clear**; the same frame made again is the same picture. What a state belongs to is the clip (or group) and the place of the effect in its chain, so the two halves of a clip that is cut each start clear, and the effect of a tag or a track has a state for each clip it is done to. The box of such a shader says *Depends on earlier frames*. **The export is exact**: it makes every frame in order. **The preview** goes on from frame to frame while it plays, and after a jump starts the effect again from nothing (a later piece makes it catch up, EN-14). Such a frame is never taken from the cache of finished frames, and **a layer that has such an effect is drawn even when something in front of it hides it** (it has to be made in every frame to go on). The states of all the effects take at most 256 MiB (the one used longest ago is let go of first) and one that is not used for 600 frames is let go of.

**Images that a shader brings (`IMPORTED`).** A shader may list images of its own, `"IMPORTED": { "name": { "PATH": "file.png" } }`, which it reads by their names like its buffers. When the file is added, **each is read from the folder of the shader or a folder below it** (a path that is absolute, goes up with `..`, or says nothing is refused: a shader is not a way to read the files of a computer), and must be a **PNG or a JPEG of at most 4 MiB and 4096 pixels across or down**, at most **6** of them (six and the picture are the 7 pictures a shader may read). Whatever is wrong is refused with the name of the shader, of the image and of the file, and the project is left as it was. **The images are kept inside the shader, in the project file** (as base 64 in the snapshot of its kind, file format 17), like its text: the project runs them where it is opened, a shader with other images is another kind, and a shader used twice with the same images is one kind. (A deviation from the plan, which had them as resources of the project: a shader, with what it reads, is one piece of data, and nothing is asked.) A shader is **given the codes of the image as the file has them** (not light: the shader works on the codes of a screen), with the opacity multiplied in as the picture of the layer is, and the top of the image at the top of the picture.

**Run so far:** filters, generators, and shaders with passes, buffers that last, and images of their own. **Kept in the project and not run** (the box says why): a transition, a buffer drawn by two passes, a last pass that draws into a buffer, and pictures that are not the layer's own or its images. Nothing is shipped in the box.

**Where the table is kept can be changed afterwards.** Right-click the heading of the box of a look-up table effect: *Include table in project file* puts a linked table inside the `.ffrs` file (if the project is not saved as one, the program asks to save it as one first, as it does for a video), and *Take table out of project file* puts an included table back where it came from, if nothing is there or the same file is (another file at that place is never overwritten: then the next place is tried, and if there is none the table stays in the file and a message says so). Where the project has several tables that could be moved, the menu also offers *Include all N tables in project file* or *Take all N tables out of project file*. Like the same actions for a video this is not an edit that undo takes back.

**The table is kept in the project** (it is a *resource* of the project: the same table used by several effects is kept once) as the setting *Files that effects use (tables of colours)* says: **embedded** in the `.ffrs` file (the default; the table is then in the file and travels with it, and a table cannot be larger than 64 MiB), **linked** (the path of the file is kept, and the table is read from there when the project is opened) or **asked about** each time a table is added. A project that is saved as plain `.json` has no room to embed anything, so the table is linked, and the program says so once. A table that is **not there** when a project is opened (a linked file that was moved) is shown in the box of the effect (*The project does not have this table.*), does nothing to the picture, and **the export asks about it**: its prompt lists the missing tables, as it lists the effects that are not installed.
