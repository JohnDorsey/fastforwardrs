# Phase 4: the effect surface, the built-in effects and the `.cube` host (design)

Written 2026-10-17, after phase 3, **before the code** (the standing rule for the engine phases). It is the design of phase 4 of [the plan of action](plugin-system-plan-of-action.md): SC-04, ID-01 to ID-09, MD-01 to MD-10, RS-01 to RS-09,
EF-01, EF-07, UI-01 to UI-07, UI-11, DS-01 to DS-03 (folders only), PH-01 to PH-05, PH-20, MG-02, LG-02, SF-02, SF-03, SF-11 and the answers Q-03, Q-10, Q-12 of [the features list](plugin-system-features.md).

Tags: **[V]** verified in the repository or by running something; **[D]** decided by the maintainer; **[P]** my proposal, which stands unless it is objected to; **[B]** my belief or estimate.
Everything here is run on **software adapters only** (SF-01).

## 0. What phase 4 is, in one paragraph

Until now the program has **one effect, the hue shift**, and everything that is built to carry effects (descriptors, instances, chains with badges, racks of keyframes, snapshots in the file, the engine's guarded shader host) was built for it and for the ones to come. Phase 4 makes the second
and the seventh: it changes **what a layer carries from "one colour matrix" to "a list of calls"**, adds the **built-in effects** (saturation, brightness and contrast, exposure, opacity, blur, crop, and the LUT effect), the **resources** that the LUT needs (a file that is embedded in the project file or linked,
with the setting for which), the **`.cube` host** (1-D and 3-D tables, tetrahedral interpolation on the card, held to ffmpeg's `lut3d`), and the **surface** that a person sees: a + menu with categories and a search field, controls made from the descriptor (sliders, choices, toggles, a file chooser), bypass, duplicate, reorder,
and a badge for an effect that the program does not have. **This is the first phase after which the program is visibly a different program.**

## 1. What is there today [V, read in the code, 2026-10-17]

* **Descriptors exist** (`project/effects/descriptor.rs`): an `EffectDescriptor` has a key (`builtin:hue_shift`), a version, a name, a description, a domain (picture or sound), `changes_each_pixel_by_itself`, and parameters, each with an id, a name, a label, a default (which fixes its kind: number, pair, colour, flag, words), a range, a unit and decimals, and
  `unknown_fields` that survive a round trip. **There is no category, no choice, no integer, no scale (linear or logarithmic), no control kind and no resource parameter.** An `EffectKind` is a `&'static` descriptor; one that a file brought is leaked into a static (`from_snapshot`) and is *installed* only if the program has a built-in of the same key and major number that has every value of the snapshot.
* **Instances, chains and groups exist** (`project/effects.rs`): an `Effect` has an instance id, a kind, values and unknown fields; an `Effects` chain has badges (tags, the track) among the instances; several instances of one kind are allowed; keyframes are racks named by the instance and the value's id. **There is no "enabled" flag.**
* **The file saves snapshots** (`plugins`, format 11), instances by value id, and keeps what it does not know; **a missing effect is kept whole** and written back unchanged. The window's export asks first when the project has effects that the program does not have (`Dialog::ConfirmExportWithMissingEffects`, `effects_the_export_would_leave_out`) [V]; what that dialog offers and what a missing effect shows in the properties panel are to be looked at in 4.7.
* **A layer carries one `ColourMatrix`.** `composition::Layer::colour_matrix_at(frame)` folds *every* effect of the layer into one matrix, and `frame_scene` turns that into one `EffectCall` (`engine:colour_matrix`, nine numbers). The old drawing (the oracle) applies the same matrix on the processor. There is no way for an effect that is not a matrix to reach the engine.
* **The engine runs** its own `engine:colour_matrix` (in the display-referred domain, converted around by two matrices and a curve in the pass: phase 3, C10) and **foreign shaders**: a WGSL fragment `fs_main`, the three bindings (≤ 64 floats of uniforms, the layer's picture, a sampler), one pass, the guard and the watchdog of phase 1.6. **A foreign effect gets the numbers of the working space**, not the display's codes (phase 3, D5): the conversion around it waits for this phase.
* **No resources exist.** A source file has a link and may be included in a `.ffrs` (`SourceMediaLink.included_as`, the archive, 64 MiB prompts do not exist); nothing else is stored in a project file by reference.
* **The + button** in the properties panel opens a plain menu (`plus_button.rs`, the properties panel) that lists the effect kinds; there is no search, no categories. Settings are a table (`project/settings.rs`) that both windows and both files are built from [V].

## 2. Decisions

| # | Decision | Why | Tag |
|---|---|---|---|
| F1 | **A layer carries a list of `EffectCall`s, not a matrix.** `composition` makes, for a layer at a frame, the calls of its chain in order (values at that frame); `frame_scene` passes them through; the engine runs them. **Neighbouring colour matrices are fused into one call** on the processor (E3: a hue shift, a saturation and a brightness make one pass); an effect that is not a matrix ends a fusion. The old drawing keeps its matrix (it can draw nothing else; a layer that has an effect that is not a matrix is drawn by the old drawing without it, and the window's own words say so when the old drawing is asked for). | The point of the phase; the fusion keeps the cost of a long chain of colour effects at one pass. | [P] (EF-01, PH-20) |
| F2 | **Every built-in effect is a descriptor and a row of behaviour** (as the hue shift is), and a behaviour is *what call it makes*: a colour-matrix row (a function of the values to nine numbers, plus three for an offset), or an engine pass by key (`engine:blur`, `engine:crop`, `engine:opacity`, `engine:exposure`, `engine:lut`). The one place that knows what a built-in does stays `built_in.rs`. | PH-20, ID-06. | [P] |
| F3 | **`engine:colour_matrix` takes 9 or 12 numbers.** 12 are the matrix and then three offsets added after it (still in the display-referred domain, cut off at 0 and 1): brightness and contrast need an offset, and no other numbers. 9 stays what it was (nothing in the tests of phases 1 to 3 changes). | The smallest change that makes brightness/contrast a colour-matrix effect and so fusable. | [P] |
| F4 | **The domain of an effect is part of its call, and the engine converts around it** (finishing C10 and D5): a call is *display-referred* (sRGB codes, Rec.709 primaries: the hue shift, saturation, brightness/contrast, the LUT with the default spaces, and every foreign shader, which is what shader files are written for) or *scene-linear* (the numbers of the working space: exposure, blur, crop, opacity). **Two neighbours of one domain are not converted twice.** | CM-10, Q-07: a blur must be of light, a saturation of codes. | [P], [D] Q-07 |
| F5 | **The built-ins**, with their values (the ids are for the file, the labels for the window): **saturation** (`amount`: 0 to 2, 1 is as it was, luma weights of Rec.709, display-referred); **brightness and contrast** (`brightness` −1 to 1, `contrast` 0 to 2, around the middle grey of the codes, display-referred); **exposure** (`stops` −5 to 5, scene-linear: a multiplication of light by 2 to the stops); **opacity** (`opacity` 0 to 1, of the layer's picture, scene-linear, before it is put in its place); **blur** (`radius`, `quality` is not offered), a Gaussian in two passes in light, **radius in points of a picture 1080 high** and scaled with the size the frame is made at, so that the preview and the export agree; **crop** (`left`, `top`, `right`, `bottom` as fractions of the layer's picture, and a `feather`, a soft edge as a fraction of the picture's height): what is outside becomes clear; **LUT** (see F8). Q-10's list, exactly. | Q-10; EF-07. | [P] |
| F6 | **Which effects may be on a group** (the placeholder of phase 3's groups: done to each member): only `changes_each_pixel_by_itself` ones, which is **hue shift, saturation, brightness/contrast, exposure and the LUT**. Not blur, crop or opacity (done to each member they are not what they would be done to the picture that the members make together). | The rule already exists in `project::groups::effects_of_groups`. | [P] |
| F7 | **Parameters get types** (ID-03, ID-05): *number* (range, step, **linear or logarithmic** scale), *integer*, *flag*, *choice* (a list of ids with labels; stored as the id in a file and as a number in the program, keyframed as a step), *pair*, *colour*, and *resource* (a reference to a resource of a kind, `cube`). A descriptor says a **category** (*Colour*, *Light*, *Blur and sharpen*, *Transform*, *Looks*) and a **control** for each parameter; the properties panel builds the control from them, not from the kind of the effect. | The surface of the phase; ID-05. | [P] |
| F8 | **Resources** (RS-01 to RS-08): a project has a list of resources, each with an id, a kind (`cube`), a name, a content hash, and where its bytes are: *included* (an entry of a `.ffrs`, `resources/...`, named as media are) or *linked* (an absolute and a relative path, as a source file is). **Embedding is the default** (RS-02); a setting in both settings windows, a row of the table (values *Embed*, *Link*, *Ask*; the project's beats the global), changes **only the resources added later** (RS-03). A **plain-JSON project cannot embed**: the resource is linked, with a note, and the program asks once whether to save as `.ffrs` (Q-03). Two instances of one table share one resource by hash (RS-05). A resource is read into memory when the project is loaded (RS-07); **the limit is 64 MiB for one resource, and a prompt above it**. A resource that is missing (a linked file that is gone) makes its instances **missing effects** (MD-07). | RS-01 to RS-08, Q-03. | [D] RS-02, RS-03, RS-07; [P] the rest |
| F9 | **The `.cube` host** (PH-01 to PH-05): reads 1-D and 3-D tables, with `TITLE`, `DOMAIN_MIN`/`DOMAIN_MAX`, `LUT_1D_SIZE` (2 to 65536), `LUT_3D_SIZE` (2 to 256), comments and blank lines, and **the DaVinci Resolve variant (`LUT_1D_INPUT_RANGE` and `LUT_3D_INPUT_RANGE`) read only**; refuses with a message that names the line what it cannot read (a size that is not what the rows say, a number that is not one, a domain that is not a range). The table goes to the card as a **3-D texture** (1-D as a strip) and is applied with **tetrahedral interpolation** (3-D) or linear (1-D). The LUT effect has *intensity* (a mix with the input, 0 to 1), *input space* and *output space* (CM-11), and *interpolation* (tetrahedral or trilinear). | PH-01 to PH-04. | [P] |
| F10 | **The spaces of a LUT** (CM-11), to begin with three, each for the input and for the output: **Screen codes (sRGB)** (the default: a table made for a screen, which is what a `.cube` that someone sends nearly always is), **Rec.709 video (gamma 2.4)**, and **Linear light (the working space)**. The pass converts the numbers of the working space to the input space, applies the table, and converts from the output space. Log spaces come with the camera logs (CM-18), which are not in this phase. | CM-11 needs a list; this is the one that three kinds of table need. | [P] |
| F11 | **File format 13** (MG-02): `resources` (their descriptions, and the entries of the included ones), an `enabled` flag on an instance (left out when true), and parameter values of the new types. A file of 12 and before loads as it was; **an older program refuses a 13** with the "newer file" message, as the colour work did for 12. The generators that were meant for 13 are 14. | MG-01, MG-03 (a version and a fixture for every change). | [P] |
| F12 | **Bypass** (UI-04, MD-09): an instance can be switched off and on from the menu of its box (and a click on its title does not do it: nothing is added to the screen that was not asked for); a bypassed instance stays in the chain, keeps its keyframes and is **not run, not counted as missing, and not fused**. Duplicate, remove and reorder (drag) exist for the hue shift already; duplicate is new. Each is a step of the history. | UI-04. | [P] |
| F13 | **A missing effect** (UI-03, Q-12): its box shows a **badge** (*not installed*) and the values from its snapshot, which can be looked at and not changed (they are kept); it is **pass-through** in the preview and the export; the export, as it does today, **asks first and lists** what is missing, with the button that exports anyway. The round trip keeps it whole [V that it is so today]. | Q-12. | [D] Q-12 |
| F14 | **The + menu** (UI-01): a button that opens a small popup with a **search field** (focused at once, matching the name, the description and the category) and the effects **grouped by category**; Enter adds the one that is first. *Add effect from file...* (UI-05) at the bottom, which opens a file chooser for a `.cube`, makes it a resource (by the embedding setting) and puts a LUT instance on the clip with it. | UI-01, UI-05. | [P] |
| F15 | **Limits** (SF-11): at most **64 instances** on one object (the number of values an effect can have, 255, is as it is); a table of at most 256³ points (that is 16.7 million points, 128 MiB as four half floats each: **refused above 65 points a side for now**, which is what the programs that people use make: the limit is a constant and a message that says so) and 64 MiB of bytes; names of embedded resources are checked as media names are (no path parts, no control characters, a length limit: SF-03). | SF-03, SF-11, RS-07. | [P] |

## 4. The tests

* **Reference first.** Every effect has its arithmetic written once in Rust (on `f32` pixels, or on `f64` where it is a table) and the card is held to it by a bound that is measured, then written down.
* **The oracle stays.** The old drawing knows matrices only, so the oracle tests run on matrices; the new effects are not compared with it (they have no counterpart): they are compared with their reference and, for the LUT, with ffmpeg.
* **The hue shift is not touched** except by being carried as a call: its tests pass as they were.
* **Round trips of what the program does not have:** an effect of an unknown key, an unknown version, an unknown parameter of a known effect, and a resource that is gone, each saved and loaded and saved, byte for byte.
* **The mutation campaign** over every new module, aimed at the right program of tests where the protection is in an integration test (the tool runs only the library's tests otherwise).

## 5. What this does not change, and what is not exact

* **Effects of groups** stay a placeholder (done to each member): phase 5 makes the picture of a group, adjustment clips and generators.
* **ISF shaders and the plugin manager** are phase 6 to 8 of the order; the folders of DS-01 to DS-03 are read for `.cube` files that ship with the program, and nothing else is scanned.
* **On-canvas handles** (UI-08) are later (Q-20). **Sound effects** are phase 7: the picture and sound domains share the list (MD-03), and sound effects are not run.
* **A blur is of the layer's picture before it is placed**: its radius is in the layer's own pixels scaled to the frame; a layer that is made much bigger or smaller by its placement is blurred by the radius as it is *in the frame* by the scaling, not in its own pixels (it is the radius of the picture the person sees, which is what they mean) [B that this is the right choice: question 1].
* **The cost.** Every effect that is not a matrix is a pass of its own on the layer; the benchmark's scene of "two blurs, a matrix and a lookup" is what this phase's effects are measured by, and its gate (60 frames to the second at 720p on the integrated graphics) is the one that you ran: it stands.

## 6. For the maintainer

Decisions that I took, and the ones I would like an answer to before the code, most important first (the default is what I will do if you say nothing):

1. **The blur's radius** is in points of a picture 1080 high, and is scaled with the frame (F5). The other choice is pixels of the layer's own picture. *Default: as in F5.*
2. **Opacity is an effect** of the chain (before the layer is put in its place), and not a property of the clip with its own control. *Default: an effect.* (Nothing about it is animated differently: it has its stopwatch.)
3. **The spaces of a LUT** (F10): screen codes, Rec.709 video gamma 2.4, linear light. *Default: these three.*
4. **Crop** has four edges and a feather. *Answered 2026-10-17: four edges and feather.*
5. **Exposure** is in stops, in light (a multiplication), and so is the only colour effect of the four that is scene-linear. *Default: yes.*
6. **The size of the phase.** It is large. I would build it in the order of section 3 and **stop after 4.4** (the call list, the matrix family, blur and crop, with the surface of 4.7 that they need to be tried) for you to try the effects, **before** the resources and the LUT. *Default: build all of it in one go and report once; say if you want the stop.*
7. **Sample LUTs** (LG-08): I would make **five of our own** (a warm and a cool grade, a contrast curve, a teal-and-orange look, a film-like fade), by formula, under CC0, with the script that made them in the repository. *Default: yes.*
8. **A 3-D table above 65 points a side is refused** (F15) for now. *Default: yes.*
