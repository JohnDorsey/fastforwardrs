# Phase 9 report: text objects are made of an effect

Written 2026-10-23, at the end of phase 9 of [the plan of action](plugin-system-plan-of-action.md), **the last phase of the plan**. How it was designed is in [its design](engine-phase-9-design.md) (decisions T1 to T9; sections 6 to 8 say what was built).
**[V]** means I ran something and saw it; **[B]** means I believe it from reading the code. Everything that drew on a graphics adapter ran on **software adapters** (WARP on Windows 10); nothing of this phase has run on a real graphics card (SF-01).

**What changed, in one paragraph.** A text object is still a clip on a track, and is edited, drawn and exported as before, but **what it says, its font, its size and its colour are now the four values of an effect, `builtin:text`, which is the first effect of its chain** (the clip keeps how long it shows and where it is). So they have keyframes, racks and the stopwatch like any value of an effect, a project file says them as the values of the effect (**format 18**), and a file of format 17 or earlier is read as a text made of the effect. The engine was not touched: a text was already a picture made on the processor and uploaded.

## 3. Tests that were changed, and why

Counted before the change (T9): the types that change were named in **21 files and 131 places in the program, and 24 files and 84 places in tests**. The tests that **were not** changed are those that use `TextObject` and the project's functions, which stay.

* **Mechanical, the same assertions:** the helpers that build a text clip now say `TextClip::new(duration, EffectInstanceId::FIRST)` (`composition/pictures/tests.rs`, `composition/sound/tests.rs`, `playback/wanted.rs`, `project/tests.rs`, `project/tracks/track/tests.rs`, `application/timeline_geometry/{tiles,waveform}.rs`, `project/tracks/clip.rs`, `project/tracks/text_object.rs`); a read of `.object` is `project.text_object_of(clip)` (`project/tests.rs`, `project/animating_tests.rs`, `project/tracks/track/tests.rs`, `fast_forward_application/text_object_tests.rs` (the helper and one test), `tests/application_journeys.rs`); a property is `test_support::{TEXT,FONT,SIZE,COLOUR}_OF_A_TEXT` (`naming.rs`, `frame_scene/section/tests.rs`, `keyframe_tests.rs`, `keyframe_panel_tests.rs`, `rack_drag_tests.rs`, `duplicate_tests.rs`, `clip_drag_tests.rs`, `generator_clip_tests.rs`, `project/animating_tests.rs`, `composition/pictures/animation_tests.rs`, `project_file/animation_tests.rs`); the random projects (`composition/test_projects.rs`) make a text by `a_text_clip_that_says` with the same numbers drawn in the same order; `tests/media_export_animation.rs` and `video_export/runs/tests.rs` name the effect's value and `LayerContent::Text(LayerEffect)`.
* **Rewritten on purpose, each with a comment that says so:**
  * `project/animation/apply.rs`: the two lists of properties (a text object's properties are those of its effect and the three of its placement), the text object's values, and the test of the text of an animated text object, which `project/animating_tests.rs` has.
  * `project/animation/property.rs`: a text clip has no `Text`, `FontFamily`, `FontSize` or `Colour` among its own properties; they are values of an effect.
  * `composition/pictures/animation_tests.rs`: **two**: the look of a text is in the effect's animation and not the layer's own; and a text object is **no longer lent from the plan** (it is made of the values), so the test that said it was `Cow::Borrowed` says what the object says.
  * `composition/pictures/{effects_tests,group_effects_tests}.rs`: the text effect is the layer's content and not one of what is done to its picture, and the first hue shift of a text is the second effect of its chain.
  * the panel: `keyframe_panel_tests.rs`, **one list** (the same reason).
  * `project_file/*` (the ones about files): the version is 18; a text's fields are the values of its effect; the badge of a tag after a text's hue shift has **two** effects before it, not one; the plugins list has the snapshot of the text effect; the example in `docs/project-file-format.md` is a file of format 18.
* **Fixtures that changed under tests of other things, and a decision I want you to know about.** Many tests of groups, effects and names use *a text clip as the clip that needs no file and lasts as long as it is asked to*, and expect its chain to be empty and its first effect to be named `0`. A text that the program makes now has its text effect first, so all of them would have changed. **I kept them as they were by changing what they build** (a few helpers: `Project::insert_a_text_clip_that_has_no_text_effect`, for tests only; `groups::test_projects::lay_out`, which uses it; `lay_out_whole_texts` and `Randomly::of_whole_texts` for the tests that need a text to be whole, because they name a clip by its words or save the project). **A text clip with no text effect is a state that a project of the program never has**; the tests that use it are not about texts, and the helper says so. I think this is the right trade (dozens of tests unmodified against a few helpers), but it is the kind of thing that a reader of those tests would not guess.
* **Deleted:** `tests/text_fixtures_writer.rs`, the 9.0 test that wrote the fixtures; it named the properties that are gone. The fixtures are what is kept (`git show 8e01c0a:tests/text_fixtures_writer.rs` has the writer).

## 5. Limits

* **I never used a real graphics card, and never looked at a text in a real window of this version.** What a text looks like is what the text drawer makes of the object, and that code and the pictures it makes were not changed; but the preview's rows, the stopwatch on the words, and the clip's label on the timeline were checked by tests of the window (a software adapter) and not by eye. [B] for how they look.
* **The model allows a text clip with no text effect** (the file refuses one; the program never makes one; such a clip makes no picture). I did not make it impossible, because `Track::with_clips` takes a clip and its chain separately and several tests use it; the cost of the guard would have been a larger change. A load of the file, and every edit that the program offers, keep texts whole [V by the tests]; a bug elsewhere that left one would show as a text that does not appear.
* **A text's keyframes of its words are offered with the stopwatch** (they were before, and the rule that a value of words has one is now stated: a box of lines or a list of fonts does; a choice does not). A value of words that another effect might have with the same controls would have it too.
* **`ClipKind::Text` and `TextObject` stay** (T1). Merging `TextClip` into `GeneratorClip` is a mechanical step I did not do and will not unless you ask.
* **Old files are read, never written:** a file of format 17 that is opened and saved is written as 18, and an older program cannot read it (it says the file is from a newer program).
* **Not changed and still true:** shaders that the program cannot run yet; the old drawing of the window that a computer with no usable adapter uses leaves out what the engine does (for a text it draws as it did).
