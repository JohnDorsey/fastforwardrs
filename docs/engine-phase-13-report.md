# Engine phase 13 report: MIDI clips that feed synthesizer effects (2026-10-28)

*Written after piece 13.6. Labels: [V] = I ran it and saw it; [B] = I believe it from reading, and could not run it. The design is [`engine-phase-13-midi-design.md`](engine-phase-13-midi-design.md): section 7 has the maintainer's answers, and section 8 has an "as built" block for each piece that says what was done and what was measured.*

## 1. What was asked

MIDI clips on the timeline that feed **synthesizer effects**, with one decision of the maintainer's: **a synthesizer is the sole consumer of the MIDI notes that reach it, by default; there is no automatic pass-through.** The answers to the four questions (all of them the recommended ones): audio that reaches a synthesizer passes by it and the synthesizer's sound is added; notes find a synthesizer **by position on the road** (the clip's own effects, the track's, the groups'), the first one wins, and a MIDI clip with none is silent and carries a marker; the exception is **a switch on the synthesizer**, not a separate effect; and notes come from **`.mid` import only** in this phase, each track of a file a clip on its own track, with a read-only piano roll (a note editor is a later phase).

## 4. What the maintainer should know (decisions I made, and what went wrong)

1. **The MIDI file is a *resource* of the project, not a source of media.** A resource already does what the file needs (included or linked, one resource for equal bytes, read once, kept when missing, not saved when nothing uses it), and a source of media is something ffprobe, the thumbnails and the decoder all assume to be a video or a sound. **The cost: a version of the program before 13.3 refuses a project that has a MIDI clip** (it would refuse file format 21 anyway).
2. **Time is in seconds from the file's own tempo map; the project has no tempo.** A clip plays the music at the speed of the project's frames; a faster clip plays its notes sooner and **not higher**. Everything about where a note is, in samples, is whole-number arithmetic (`u128`), rounded down once.
3. **Edges:** a note that began before the clip is **not played**; one held at the clip's end is let go there; one that is sounding where a stretch begins (a seek, or the end of a mute) is **chased**: started at the start of the stretch. The pedal and the pitch wheel are put back at the end of a stretch, so that the next clip on the same synthesizer does not begin with a pedal down.
4. **A synthesizer is a plugin with no audio input and a note input**; one with an audio input is an effect even if it takes notes. LADSPA has no notes and is never one.
5. **The consumption rule, exactly:** the notes go along the road; a chain with no synthesizer lets them by; in a chain, the first synthesizer plays them and so does a later one only if every one before it passes them on; they go on to the next chain only if every synthesizer of this one does. **A synthesizer that is not installed still takes the notes** (so that another does not play them in its place).
6. **A finding that changed behaviour: a synthesizer now holds back the sound that passes by it by its own latency.** Before 13.5 a source plugin added its output without delaying what passed, so with a latency `L` the passing sound came out `L` early against what the synthesizer made. It was invisible while the passing sound was silence, and it showed when the notes went through two synthesizers (found by the test of two synthesizers with different latencies). Plugins that report no latency are not changed.
7. **Words you can see were changed on purpose:** the question of the import items is now "Choose a video, a sound, a picture or a MIDI file", the first kind "Video, sound, picture and MIDI files", and there is a kind "MIDI files" (the tests that pinned the old words were changed with them). There is no new menu item: the same two items take `.mid`.
8. **File formats:** 21 (the MIDI clip, `makes_sound_from_notes` in a snapshot) and 22 (`passes_notes_on` in an effect). A version 20 or 21 file is read as before.
9. **What went wrong:** (a) the 13.4 commit made CI fail in the *Documentation* step of the Ubuntu job (`cargo doc --document-private-items` with `-D warnings`): a public doc comment linked to a private function. Everything else was green; it is fixed in `76d0b6d`, and **I now run that exact command before every push**. (b) A script of mine put a stray control character in the memory index and a heredoc once halved backslashes in a test file: both found and repaired the same day.
10. **A limit of the piano roll worth knowing:** only the notes in view are looked at, and a note longer than **two minutes** that begins before the part in view is not drawn in it (noted in the code).

## 5. What is open for the maintainer

* **Real synthesizers have not been tried** (Kars, Nekobi, Surge XT, as the design said for 13.7). The bundled set has Surge XT's *effects* and no synthesizer, so trying a real one means **downloading** one (a release file from its authors) or pointing the plugin manager at one you already have. I did not download anything without asking. Until then, what is proven is the host's side with the test instruments, not the behaviour of a real plugin's note handling (its voices, its release, its latency, its window, its presets).
* **Listening:** I can check samples, not music. A listen to a real tune through a real synthesizer is the check that no test of mine can be.
* **A bigger piano roll, and the note editor** (a later phase, Q4), **MIDI effects** (a note in and a note out), **several note ports of one plugin**, **notes in the windows of a track that takes a window of its effects** (`PerTrackWithWindows`: the one instance plays the notes of the whole track), and **a marker for a MIDI clip whose file is missing** (it is silence, as a sound's is, with no special word).
* Whether a synthesizer should stay under one *Synthesizers* heading in the menu whoever made it, or be listed by maker as the other plugins are.
