# Phase 9: text objects become generators (design)

Written 2026-10-22, from the plan's phase 9 ([`plugin-system-plan-of-action.md`](plugin-system-plan-of-action.md)), EF-06, SC-05, ID-05 and Q-17 of [the features list](plugin-system-features.md), the generator clip of phase 6.5 ([`engine-phase-6-design.md`](engine-phase-6-design.md)),
and the code as it is. Tags: **[V]** verified in the code or by running something; **[D]** decided by the maintainer; **[P]** my proposal, which stands unless it is objected to; **[B]** my belief.

**Effort I suggest: high** (the plan says M-L). **Riskiest piece: 9.2 to 9.4 together** (section 4): the model, the picture and the file change under each other and cannot be shipped one at a time.

## 0. What was asked [D]

* The plan (2026-10-15): *Text becomes a generator effect with the parameters it has today (text, font, size, colour), drawn on the CPU and uploaded (a second kind of host, "CPU image producer"). One migration from format 11. Done last because it changes a lot for no new capability and benefits from a settled model. Gate: every text test passes unmodified except the file-format ones; old projects look the same.*
* Q-17 (2026-10-15, default accepted): *later, once the plugin model has settled.* The maintainer said on 2026-10-22, when they could not do experiments at home: **"continue to phase 9"**. The model has settled (phases 4 to 6 are built).
* (The plan says "format 12" and "from format 11": the file format is **17** now, so the migration is to **18**.)

## 1. What there is [V, read 2026-10-22]

* **A text object** is `Clip::Text(TextClip { object: TextObject { text, font_family, font_size (a fraction of the picture's height; shown as points on 1080), colour: TextColour (straight RGBA, 8 bits), area, rotation }, duration_in_frames })`, kind `ClipKind::Text`. `Clip::Text`, `ClipKind::Text` and `as_text()` are named in **39 places of the program** (the largest groups: `project/tracks/clip.rs` 7, `project/animation/property.rs` 4, `project/animating.rs` 4, `project/tracks/track/editing.rs` 3, `project_file/mod.rs` 3), and the text types in about **70 files that have tests** (about 100 mentions in tests: the model, the keyframe tests, the preview, the export, the file format).
* **What a text says and how it looks can be animated**: the clip's own properties `PropertyId::{Text, FontFamily, FontSize, Colour}` (kinds *words*, *words*, *number*, *colour*), with keyframes, racks and the stopwatch buttons like any property; `Project::text_object_at(clip, frame)` is the object at a frame; where it is (`Position`, `Size`, `Rotation`) is the placement that the generator clip has too.
* **A generator clip** (6.5) is `Clip::Generator(GeneratorClip { duration_in_frames, content: EffectInstanceId, placement })`, **and its content is the first effect of its chain**: an effect that takes no picture, whose values are properties like any effect's (keyframes, controls, a place in the file with no more code). The content cannot be taken off, switched off, copied or moved (`Project::the_clip_whose_content_is`); `Track::insert_generator_clip_at(frame, kind, frames)` makes the clip and puts the content on it.
* **The values of an effect are `PropertyValue`s**: *number*, *pair*, *colour* (the same `TextColour`), *flag*, *words*; a descriptor says the control (`ParameterControl::{Automatic, Slider, Integer, Toggle, Choice, Resource}`); *words* with `Automatic` are a text field. The built-in effects are statics (`project/effects/built_in.rs`), their descriptors never change without a new version, and a project file keeps a snapshot of the descriptor of each effect it uses.
* **A text is already a CPU image producer, and the engine does not know it**: the preview and the export describe a text layer as `PreviewLayerContent::Text(object)`; `frame_scene/describe.rs` makes its picture with `TextPictures::text_picture` (the text renderer, on the CPU, once the fonts are loaded: `HowToMakeIt::Text`), and it goes to the engine as **a picture** under an id made of the text's look (`KindOfPicture::Text`). So "the second kind of host" is a name for something that exists: nothing in the engine changes for text, and no shader runs for it.
* The file has `Text { text, font_family, font_size_fraction_of_frame_height, colour, area, rotation_degrees, animation, drawer, effects, badges }` and `Generator { content, area, rotation_degrees, drawer, effects, badges }` as entries of a track (`project_file/document.rs`); keyframes are by property name (`"text"`, `"font"`, `"font size"`, `"colour"` for the clip's own; an effect's by the id of its instance and of the value).

## 2. What I propose [P]

| | | why |
|---|---|---|
| **T1** | **A text clip is a clip whose content is the effect `builtin:text`**, as a generator clip's is: `TextClip { duration_in_frames, content: EffectInstanceId, placement }` with the content the first effect of its chain, **and the kind stays `ClipKind::Text`**. The two clip kinds are not merged now. | The plan says the text becomes a generator *effect*; this does that (the text is the *content*, an effect with values, keyframes and a descriptor) and keeps the 39 places, the timeline's names and tiles, the selection, and the dispatch of the properties panel as they are. Merging `TextClip` into `GeneratorClip` (a tag in it, and no `Clip::Text`) is the cleaner end, touches the same places and about a hundred tests, and can be done afterwards as a mechanical step: **I do not do it unless you ask**. |
| **T2** | **`builtin:text`**, version 1.0, domain *picture*, category *Generators*, no shader. Its values, in this order: `text` (*words*, the control *Multiline*, default `Text`), `font` (*words*, the control *Font*, default empty = the program's font), `size` (*number*, **a fraction of the picture's height**, the control *Points of the picture's height*, default 0.06), `colour` (*colour*, default white). | The values are what a text object has today, and the **fraction stays the stored value** so that a project that is migrated makes the very same pixels: points would be the fraction times 1080 in `f32` and back, which is not always the same number, and the size in pixels that the text renderer is given would differ in its last bits. |
| **T3** | **Q-17 / ID-05 answered: a font is a *words* value with a control** (`ParameterControl::Font`), not a new kind of value. The controls added are `Multiline`, `Font` and `PointsOfThePictureHeight`. A font that the computer does not have is kept as it is, and the program's font is used, as now. | Nothing in the animation (a words value holds until the next keyframe), the file (a string) or the keyframe code changes: only the panel's row. |
| **T4** | **Where the text is stays the clip's**: `Position`, `Size`, `Rotation` (the area and the turning) are the clip's own properties, as for a generator and a picture. | They are properties of the clip and not of an effect, and the box on the preview moves them. |
| **T5** | **`TextObject` stays** as the value that the panel, the commands (`NewTextObject`, `SetTextObject`), `Project::insert_text` and `text_object_at` speak in: it is **read from and written to the values of the content** (and a keyframe where the value is animated, as `SetTextObject` does today for the properties that have keyframes). `PropertyId::{Text, FontFamily, FontSize, Colour}` go; the same four are `EffectValue` properties of the content (and the rows of racks and the lists of keyframes follow, since they are by property). | What a person or a test does with a text through these does not change. |
| **T6** | **The describer reads the values of the content at the frame** (the content's values with its keyframes applied, which is what `text_at` does for the clip's own today) and makes `LayerContent::Text(object)` of them; the rest of the chain is done to the picture, as to a picture of a video. **The engine is not touched.** | The picture of a text is made by the code that makes it now. |
| **T7** | **The migration, format 18** (`project_file`): a text entry of a file of format 17 or less is read as it is (its fields stay readable: `legacy_text`) and becomes a text clip whose chain has `builtin:text` first (with a snapshot of its descriptor), **with the object's four values, and the keyframes and the racks of the four properties moved to the values of that instance**; the other effects of the clip are after it, as they were, with the names they had. Saved, it is the new entry (`content`, `area`, `rotation_degrees`, `effects`, `drawer`, `badges`), as a generator is. A file of format 18 that a program of format 17 opens is refused as always (`file_format_version` too new). | One migration, as the plan says. |
| **T8** | **The properties panel keeps its rows** (text, font, size, colour, how long) and binds them to the values of the content (`Animatable::of_an_effect`) instead of the clip's own properties. The content shows in the chain as a generator's does and cannot be taken off, switched off, copied or moved (the rule of `the_clip_whose_content_is` covers it). | **Nothing a person sees changes** (UI rule: no new always-visible interface). |
| **T9** | **The gate, made stricter and made honest.** *Old projects look the same*: **before any change**, fixtures are saved by the program as it is (a text, a text with keyframes of each of the four, one with racks, one with effects, one in a group, one over a video), and the pictures that the engine makes of them at several frames are kept as hashes in the tests (9.0); after the migration they must be the same, pixel for pixel. *Every text test passes unmodified*: **this holds for every test that works through the API (T5) and the pictures**; it **cannot** for a test that builds a `TextClip` itself or reads `text.object` or names `PropertyId::Text` (the model's shape changes under it). Those are **changed mechanically (the same assertions, the new way of building)**, and **listed in the report**, as the tests that were rewritten on purpose are in phase 6's. | The plan's gate was written before the shape of the code was known. |

## 3. What this does not do

* A text that is a *shader* (a different way of drawing text) is not built; nor are outlines, shadows, boxes behind the text, or more than one style in a text. They are new capabilities (the plan: "for no new capability").
* The two clip kinds are not merged (T1).
* The text of one clip is not made available to another clip.

## 6. 9.0 as built [V, 2026-10-22]

**What it is.** Six project files of format 17 that the program wrote before phase 9 (`tests/data/text/*.json`: a plain text, one whose words, font, size, colour, place and turning change, one with effects on it and on its track, one whose keyframes are in racks that were taken out onto a crate and merged, one cut in two with keyframes across the cut, one in a tag, a clip group and a track group with an effect each; made by `tests/text_fixtures_writer.rs`, a test that is marked to be ignored and goes with the properties it names in 9.2), and one test program, `tests/text_objects_as_they_are.rs`, that reads each, describes up to 39 of its frames (the list is in the test) as the preview and the export do (`video_export::FrameDescriber`; a text drawer that draws no letters but a picture made of the text, the font, the size, the colour and the size of the area), and compares what it finds with `tests/data/text/*.expected.txt`, which the program wrote before any change. For each frame the expected text has **the text object that each text clip is at it** (every property, keyframes applied), **what the text drawer was asked to draw**, and **every layer** (its corners, the picture it has, every effect with its numbers, and the layers of a group inside it). No ids are in it (they come from hashes). The numbers that sines and cosines make (the corners of a turned layer, the matrix of a turn of the hues) are written to five decimals, because the last bits of a sine are not the same on every computer; everything else is in full.

**It is an integration test that uses only what is public and stays public** (`project_from_json_text`, `plan_export`, `FrameDescriber`, `Project::text_object_at`, `TextObject`), so it is **not changed by phase 9** and needs no graphics adapter, no fonts and no ffmpeg. It runs on every computer that CI uses.

**What it caught when I tried it** (planted mistakes in the code that reads the values of a text at a frame): the words, the font, the size and the colour not following their keyframes are all noticed. Two others were not and are not its business: a first half of a cut text that is a frame too long, and the reading of the size of the font as a property value of an object (`text_value`), which are used when something is edited and not when a saved file is read and drawn (the unit tests have them).

**The places that name the types that change** (`TextClip`, `Clip::Text`, `PropertyId::{Text, FontFamily, FontSize, Colour}`, `text_value`, `with_text_value`, `PROPERTIES_OF_A_TEXT_OBJECT`), counted before any change: **in the program, 21 files and 131 mentions**, the most in `project/animation/apply.rs` (38), `project/animating.rs` (13), `project/tracks/text_object.rs` (9), `project/tracks/clip.rs` (9), `project/animation/property.rs` (8), `project/tracks/track/editing.rs` (7), `application/properties_panel/text_properties.rs` (7), `project/mod.rs` (6), `application/fast_forward_application/animating.rs` (6), `project_file/mod.rs` (5); **in tests, 24 files and 84 mentions**, the most in `composition/test_projects.rs` (8, the random projects), `composition/pictures/tests.rs` (8), `project/animating_tests.rs` (7), `composition/pictures/animation_tests.rs` (6), `application/fast_forward_application/keyframe_tests.rs` (6), `keyframe_panel_tests.rs` (6), `project_file/animation_tests.rs` (5). These are the tests that can need a mechanical change in 9.2 to 9.4 (the others only use `TextObject` and the project's functions, which stay); the report lists the ones that did. (The estimate in section 1 of "about a hundred" was of every mention of any of the text types, `TextObject` too; **`TextObject` stays**, so the number that matters is this one.)

## 7. 9.1 as built [V, 2026-10-22]

* **`EffectKind::TEXT`**, `builtin:text`, version 1.0, domain *picture*, category *Generators*, name `text`: four values, **`text`** (words, a box of lines, begins as nothing), **`font`** (words, a list of fonts, begins as nothing = the program's font), **`size`** (named *font size* when it is told apart; a number that is **a fraction of the picture's height** from 0.01 to 0.5, begins as 0.06, shown in `pt`) and **`colour`** (a colour, begins white): the values and the order of a text object. The words begin as nothing and not as `Text` because **a word cannot be made in a static** (the built-in descriptors are statics); whoever makes a text clip puts `TextObject::NEW_TEXT` in, as the rest of a new text object is put in.
* **It is not in `EffectKind::BUILT_IN`**: that list is what every other thing is *offered*, and some twenty generic tests go through it (every built-in effect can be put on a video, has an operation, is in the menus...), none of which is true of a text. It is in **`EffectKind::BUILT_IN_CONTENTS`** (the effects of the program that a clip is made of and that are not done to a picture), which `from_snapshot`, `built_in_with_key` and `is_installed` look in as well. **Only a text clip can have it** (`applies_to_a_clip_of_kind`; not a track, not a group of any kind), it asks nothing of a picture, and `is_a_generator()` is still about shaders only.
* **Three controls, in the descriptor, the file and the panel**: `ParameterControl::Multiline` (words in a box of four lines), `Font` (words chosen from the fonts of the computer: the default, then each; a font the computer does not have stays chosen as it is kept; *"Looking for the fonts..."* while they are not known) and `PointsOfThePictureHeight` (a number that is a fraction of the picture's height, shown as the points that it would be on a picture 1080 tall, brought back inside what a text can be, as `FontSize` does). The descriptor refuses a control on the wrong kind of value (a box of lines or a font on a number, a size on words); the file names them `"multiline"`, `"font"` and `"points_of_the_picture_height"` in the snapshot of an effect (another effect that has them is read with them and written back as it was). The rows are drawn by `control_for` (the generic row of any effect's value; it is given the fonts, from the `PropertiesContent` that the panel has), so **in 9.5 the text panel's rows are these rows** and not a second copy; for now `text_properties.rs` shares their two constants.
* **Nothing uses the effect yet**: no menu offers it, no clip has it, and what a user sees is as it was.
* **Tests (all new, nothing older changed):** 6 of the descriptor (`project/effects/text_tests.rs`: its values, kinds, defaults, controls and range; not offered, found by its key, stands in for its snapshot and for a snapshot with fewer values; only a text clip can have it; asks nothing of a picture; the controls fit the kinds of value), 3 of the file (`project_file/text_effect_tests.rs`: the snapshot names the controls and the effect comes back as the program's; it is refused on a track; another effect with the three controls round-trips), 4 of the rows (`properties_panel/effects/controls_tests.rs`: typing into the box of lines, choosing a font and going back to the default, a font that is kept but not there and the wait for the fonts, the size in points and its limits). **24 planted mistakes in this piece, 22 noticed at first**; the two that were not (the size in points read as nothing, which a snapshot of the program's own effect hides because the program's descriptor stands in for it; and a size kept past what a text can be, which the box of dragging clamps when it is typed in but not when it is shown) got tests and are noticed.

## 8. 9.2 to 9.5 as built [V, 2026-10-23]

The model, the picture, the file and the panel were done together, as 9.2 to 9.4 said they must be (and 9.5 followed at once, since the panel had to stop drawing the text twice the moment the text became an effect).

* **The model (T1, T5).** `TextClip { duration_in_frames, content: EffectInstanceId, placement }` (it is `Copy`: it no longer owns a `TextObject`); `Clip::content()` says which effect of its chain a generator clip or a text clip is made of, and `Project::the_clip_whose_content_is` is the one rule for both (**the third of the things I did not know in section 5**: it needed no second rule; it asks `Clip::content()`). `PropertyId::{Text, FontFamily, FontSize, Colour}` are gone and so are `text_value`, `with_text_value` and `PROPERTIES_OF_A_TEXT_OBJECT`; the four are `PropertyId::EffectValue` of the text effect, **`properties_of_the_text_effect(content)`**, in the order `[text, font, size, colour]`, and a text object's seven are **`properties_of_a_text_object(content)`** (those four and `Position`, `Size`, `Rotation`). `values_of_a_text_object` and `text_object_of_values` turn a `TextObject` into the four values and back (a value that is missing or of another kind is what a new text has; a size is brought inside what a text can be, as `FontSize` always did). `Project::text_object_of(clip)` (not animated) and `Project::text_object_at(clip, frame)` (as the keyframes say) are what the preview, the export and the tests read; `Project::set_text_object` and `Track::set_text_object` write the four values into the effect and the place into the clip; **`Track::insert_text_at` makes a text whole: the clip, then its text effect as the first of its chain, then what it says**.
* **The picture (T6).** The layer of a text clip has the text effect **taken out of its `effects`** (so that the effects done to it keep their places, and the states of the effects that keep something from one frame to the next keep their names) and has it as `LayerContent::Text(LayerEffect)`, with its values and the keyframes of them; `Layer::text_at(frame)` makes the object from the values at the frame and the layer's place at the frame. A text clip that has no text effect (which a project that is whole does not have) makes no picture.
* **The file (T7), format 18.** A text clip is written with `content` (the name of its text effect in its `effects`) and its place, and **no longer has `text`, `font_family`, `font_size_fraction_of_frame_height` or `colour`**: they are the `values` of the effect. **A file of format 17 or earlier** (the four fields in the clip, no `content`) is read as a text whose text effect is **the first of its chain, named with `Effects::next_instance()`** (so the other effects keep their names, and the racks that name them still do), whose values are the four fields (a missing size, font or colour is what a new text has; **missing words are an error**, as before), and whose badges that were before the first effect come after it; **the racks of `text`, `font`, `font size` and `colour`** (which had no `effect`) are racks of the values of that effect (`FileContents::value_of_the_text_that_a_file_of_an_earlier_version_calls`). A file that names a `content` that is not a text effect of the clip is refused with the clip named. `docs/project-file-format.md` has the format, and its example is a file of format 18 (a test loads it).
* **The panel (T8), and one change that a person can see: none.** The rows of a text (what it says, the font, the size, the colour, how long, where) are where they were, in the box of the text; the four are now **the rows that any effect's values have** (`show_the_control_of`, with the three controls of 9.1), and the effect is **left out of the boxes of the chain** (`chain.rs`, `is_what_a_text_says`), as it is not offered in the **+** menu and cannot be taken off, switched off, copied or moved. One rule of the rows changed so that the stopwatches stay: **a value of words whose control is a box of lines or a list of fonts has the stopwatch and the buttons of keyframes** (it holds until the next keyframe); a choice and a switch still have none.
* **The gate (T9).** `tests/text_objects_as_they_are.rs` and its files, **unmodified** (the six files of format 17 that the program wrote before the change, read by the new program, and every frame's text object, text drawer request and layer, compared with what the program said before the change): **6 of 6 pass**. The same, in words: *the pictures that the engine makes of old projects are the same at 39 frames of six projects, as numbers*, and a file of format 17 is read as a project that looks the same. (What this does not say: that the letters come out the same on the screen of a computer with fonts; the text drawer of the test draws no letters. The path that draws them was not changed: the text is still a CPU picture, `HowToMakeIt::Text`.)
* **Tests that were changed, and why (the list that T9 promised).** **The panel's assertions were not changed**: `text_object_tests.rs` reads the object through `text_object_of` (the helper `text_clip` and one test of a saved file, 12 lines) and `keyframe_panel_tests.rs` has the three constants and one list (the first hue shift of a text is the second effect of its chain). The rest are the tests that **name what changed shape**: they build a `TextClip` themselves, or read `text.object`, or name `PropertyId::Text` and the others, or were about files of format 17. **In the program's tests**: the helpers that build a text clip (`composition/pictures/tests.rs`, `composition/sound/tests.rs`, `playback/wanted.rs`, `project/tests.rs`, `project/tracks/track/tests.rs`, `application/timeline_geometry/{tiles,waveform}.rs`, `project/tracks/clip.rs`, `project/tracks/text_object.rs`) say `TextClip::new(duration, EffectInstanceId::FIRST)`; the reads of `.object` say `project.text_object_of(clip)` (`project/tests.rs`, `project/animating_tests.rs`, `project/tracks/track/tests.rs`, `tests/application_journeys.rs`); the properties are `test_support::{TEXT,FONT,SIZE,COLOUR}_OF_A_TEXT` (`naming.rs`, `frame_scene/section/tests.rs`, `keyframe_tests.rs`, `keyframe_panel_tests.rs`, `rack_drag_tests.rs`, `duplicate_tests.rs`, `clip_drag_tests.rs`, `project/animating_tests.rs`, `composition/pictures/animation_tests.rs`, `project_file/animation_tests.rs`); `composition/test_projects.rs` (the random projects) makes a text by `a_text_clip_that_says` with the same numbers drawn in the same order as before; `tests/media_export_animation.rs` and `video_export/runs/tests.rs` name the effect value and `LayerContent::Text(LayerEffect)`. **Rewritten on purpose**, each with a comment that says so: `project/animation/apply.rs` (the two lists of properties, and the text object's values, in place of the three that named `PropertyId::Text`; and the test of the text of an animated text object, which `project/animating_tests.rs` has), `project/animation/property.rs` (a text clip has no `Text`, `FontFamily`, `FontSize` or `Colour` among its properties: they are values of an effect), `composition/pictures/animation_tests.rs` (**two**: the look of a text is in the effect's animation and not the layer's own, and a text object is no longer lent from the plan, so it is not `Cow::Borrowed`), `composition/pictures/{effects_tests,group_effects_tests}.rs` (the text effect is the layer's content, not one of what is done to its picture; the first hue shift of a text is the second effect of its chain), `project_file/*` (the version is 18, the text's fields are values of an effect, and what is the second effect and not the first), `application/fast_forward_application/keyframe_panel_tests.rs` (**one list**: the first hue shift of a text is the second effect of its chain).
* **Fixtures that changed under the tests of other things (a decision to be told).** Many tests of groups, of effects and of names use *a text clip as the clip that needs no file and lasts as long as it is asked to*, and expect its chain to be empty and its first effect to be named `0`. A text that the program makes now has the text effect first, so those tests would all have changed. **I kept them unmodified instead, by changing what they build**: `Project::insert_a_text_clip_that_has_no_text_effect` (for tests only) makes a text clip **without** its text effect, with the content name `u32::MAX` that no chain gives out (so that an effect that a test puts on it is never taken for what it is made of), and `groups::test_projects::lay_out` uses it (and `lay_out_whole_texts` makes whole ones, for the tests that need what a text is called by its words, or that save the project: `group_messages`, `group_refusal_tests`, the random edits that are saved). **This is a state that a project of the program never has** (a text clip with no text effect), kept for the tests that are not about texts; the tests of texts use whole ones. I think it is the right trade (about 60 tests unchanged against a few helpers), but it is a thing that a reader of those tests would not guess, so it is said at each helper.
* **New tests.** `project_file/old_text_files_tests.rs` (6): the helper that writes a file as the version before 18 did (`as_a_file_of_a_version_before_18`, which the tests of other old files use, so that the project of everything's text does not stop them being what they are), and that a text of an old file becomes a text made of its text effect, first, named after the others; that the keyframes of what it said are those of the values; that a badge before its first effect comes after the text effect; that an old text with a bad colour, no words, no size, no font or no colour is refused or is a new text's; and that a new file whose text names a content that it has not, or one that is not a text effect, is refused.
* **Deleted.** `tests/text_fixtures_writer.rs` (the 9.0 test that wrote the fixtures; it named the properties that are gone; the fixtures are what is kept, and `git show 8e01c0a:tests/text_fixtures_writer.rs` has it).
